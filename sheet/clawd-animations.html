Clawd Animation Sheet

Thirteen pixel animations for Clawd in the clawd-watch plugin, each matched to something Claude can be doing. Copy any one as a standalone SVG and drop it into the plugin's drawing.

Alternatives

Twenty-five other ways Clawd could fill a phase, so a long wait does not repeat one animation. The tag on each says which phase it could stand in for. None of them is in the plugin yet.

State switches

Every switch clawd-watch makes in the current version (0.13.0), from when the band shows up to which frame Clawd moves to next. Times count from the moment Claude went quiet (the start of the quiet stretch). Clawd checks once a second, so a timed switch lands up to a second late.

ShownHiddenThe last tracked task ends (its notice arrives, TaskStop, the agent list shows it ended, it is older than 2 hours) or /clawd-reset runs.

2. The quiet stretch: started, carried on, restarted

Situation when the band showsWhat happens
No stretch under wayA new one starts: wave straight away, or hop if a task ended during the turn before. Timers start at 0.
A stretch is under way, no task endedIt carries on: no new opener, timers keep running (a task notice that wakes Claude does not restart the wait).
A stretch is under way, a task endedIt restarts with a hop, reached through the current animation's exit, and the timers go back to 0.
The person types a promptThe stretch is cleared, so the next quiet moment opens fresh with a wave.
No tasks left, or /clawd-resetThe stretch is cleared.

4. Which task, and its animation

Task the band showsAnimation
Any task whose description or command reads like a search (rg, grep, find, "search", "look for", "explore", "scan")Searching
Background agent whose description reads like writing ("write", "implement", "fix", "refactor", "add", "update", "draft"…)Writing
Any other background agentThinking
Command that tests, builds, installs, lints or deploysThinking
Any other command, or a MonitorListening
Only servers or watchers left (npm run dev, vite, docker compose up, tail -f…, or any command past 10 minutes)Idle, text says "Running in background"

The task shown is the newest one Claude waits on, or the one picked with ‹ ›. It changes, and so can the animation at the next tick, when a task starts or ends (which also drops the ‹ › pick), when the person steps with ‹ ›, or when a command passes 10 minutes and turns into a background one.

5. How one animation hands over to the next

SwitchFrames played
Any A to a different BA's exit (props leave, Clawd eases back to standing), then B with its entrance (a squash while its props pop in). B starts 50 ms after the exit ends.
Writing ↔ stretchStraight across, no exit or entrance: the laptop stays put.
Exit still playing, target changes againThe exit finishes, then goes straight to the newest target.
Target equals what is playingNothing changes; the loop is not restarted.
A new stretch with no stretch before itThe opener appears at once, with no exit.

Exit lengths: idle, wave and hop 450 ms; listening, thinking, writing, stretch, searching and scrolling 500 ms; sleeping 700 ms (Clawd wakes up first). On the desktop app the old frame stays underneath the new one for 200 ms so the switch never flashes blank.

TimeMark

The opener, breaks and exits never show in the slim line: the mark stays on the phase they interrupt. It also changes when the task shown changes. In the terminal, the band is one line of text instead ([o_o] Waiting on …) and shows no animation at all.

Fan-made sprite drawn for clawd-watch: a 14 × 8 pixel body in a 32 × 22 frame, built from nested parts (body, arms, legs, eyes, shadow) that each move on their own. Animations use CSS keyframes inside each SVG, so they keep running wherever the SVG is shown.
